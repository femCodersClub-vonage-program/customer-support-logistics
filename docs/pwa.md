# Client PWA

The customer app (`apps/client`) is a PWA. The manifest and service worker are generated by [`vite-plugin-pwa`](https://vite-pwa-org.netlify.app/) from `apps/client/vite.config.ts`.

## How it behaves

- **Install prompt:** the "Install the app" card on **My orders** uses the native install dialog on Android (Chrome, Edge, Samsung Internet) and shows the Share → "Add to Home Screen" steps on iOS Safari. It is hidden when the app is already installed, for 7 days after "Not now", and while interruptions are blocked.
- **Updates:** a new deploy shows a "New version available" message. The app only reloads when the user taps **Reload**.
- **Blocking interruptions:** a page calls `useBlockInterruptions()` (from `apps/client/src/pwa/interruptions.ts`) to hide the install and update messages, e.g. during the mediation call (`/call/:id`) or while a form has unsaved changes (`useBlockInterruptions(isDirty)`).
- **Language:** the manifest (`name`, `description`, `lang`) only holds one language, so it is in Spanish, the default. Once open, the app follows the user's language (see [i18n](i18n.md)).
- **Offline:** the app shell is precached, so deep links open from the installed app and an offline message is shown when there is no connection. Full offline support is out of scope.

## Testing on a phone

Service workers and installation need a secure origin, so `localhost` only works on your own machine. To open the app from a real phone, expose it through an HTTPS tunnel with [ngrok](https://ngrok.com/docs/getting-started/).

### One-time setup

1. Create a free ngrok account and [install the CLI](https://ngrok.com/download).
2. Add your auth token:

   ```sh
   ngrok config add-authtoken <your-token>
   ```

### Start the tunnel

Use a production build, so the service worker, the update message and the offline behaviour work as they will for customers:

```sh
pnpm --filter ./apps/client run build
pnpm --filter ./apps/client run preview
ngrok http 4173
```

ngrok prints a public `https://…ngrok-free.app` (or `.ngrok-free.dev`) URL. Vite only accepts the ngrok hosts listed in `server.allowedHosts` in `apps/client/vite.config.ts`. Requests to `/api` are proxied to the local API, so keep it running (`API_URL` overrides the target).

For quick UI checks you can tunnel the dev server instead (`pnpm --filter ./apps/client run dev` and `ngrok http 5173`). It uses a development service worker, so don't rely on it for update and offline checks.

On the free plan, ngrok shows a warning page the first time you open the URL. Tap **Visit Site** to continue.

### Install the app

- **Android (Chrome, Edge, Samsung Internet):** open the ngrok URL, go to **My orders** and tap **Install** in the "Install the app" card. If the card doesn't appear, use the browser menu → **Install app**.
- **iPhone / iPad (Safari):** open the ngrok URL in Safari, tap **Share** → **Add to Home Screen** → **Add**. The "Install the app" card on **My orders** shows the same steps.

The installed app opens standalone, with the "CSL" name and icon and the `#871eff` theme colour.

### What to check

- **Install prompt:** it doesn't show once the app is installed, for 7 days after "Not now", or on `/call/:id`. To show it again, clear the site data for the ngrok URL.
- **Updates:** rebuild and restart `preview` while the app is open. A "New version available" message appears, and it doesn't appear on `/call/:id`.
- **Deep links:** open `/incidents/123` or `/call/123` directly from the installed app.
- **Offline:** turn on airplane mode and reopen the app. It loads and shows the offline message.
- **Manifest:** on desktop, Chrome DevTools → Application → Manifest shows no installability errors.

The ngrok URL changes every time you start the tunnel, unless you use your free [static domain](https://ngrok.com/docs/universal-gateway/free-static-domains/) (`ngrok http 4173 --url=<your-domain>`). Each URL is a separate origin, so the app has to be installed again.
